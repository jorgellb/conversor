# Recetas: cómo se añade una herramienta

Extraído del código el 14/11/2026 (lotes F5-C, F5-B1, F5-F y F3-B). Lo usan los agentes implementadores junto con `docs/GOAL.md`. Si el código cambia, manda el código.

Numeración de decisiones: read the last row of docs/DECISIONS.md before adding one (D-142 after the review of G0-A; batches run in parallel, so check again right before committing). Format: a Markdown table row in docs/DECISIONS.md `| D-NNN | <decision text> | <motivo, citing spec section numbers such as '6.3 y 6.5' or 'Desviación de 5.4 ...'> |`, three-digit zero-padded from D-001 (D-01 to D-99 appear as two digits, e.g. D-01 and D-96; from D-100 on, three). Batches cite their range in PLAN.md and PROGRESS.md as 'Salvedades en D-a a D-b' or 'Hecho (D-a a D-b)'.

## Herramienta de servidor

1. Reference batch: F5 lote C (heic-a-jpg, heic-a-png, raw-a-jpg, psd-a-png, png-a-svg, jpg-a-svg, quitar-fondo; D-95 to D-99). Traced example: psd-a-png / quitar-fondo. The repo has a single git commit (2debe70), so these steps come from reading the code, not from diffs.
2. STEP 0 - Read the spec first: the catalog line in docs/spec/07-7-catalogo-completo-de-herramientas.md (format 'slug - engine - phase'; keep slugs exactly as written), the options in the matching Anexo A file (docs/spec/a-*.md, e.g. a-10-a-10-imagenes.md; conventions in a-0-a-0-convenciones-comunes.md), the worker group and engine in docs/spec/05-5-arquitectura-y-flujo-de-trabajos.md §5.4, and the license rules in docs/spec/11-11-licencias.md. When the Anexo A sets no options, choose the simplest ones and record them as a D-NNN in docs/DECISIONS.md, cited in the Options docstring (e.g. 'quitar-fondo con rembg (6.4); el Anexo A no fija opciones (D-96)').
3. STEP 1 - Python dependency (if new): pin the exact version (==) in the group's optional extra in /pyproject.toml (e.g. `media = [... "psd-tools==1.26.0", "rembg==2.0.86" ...]`) and add a comment that cites the batch and the license trap. Check the license and its transitive dependencies and extras against 11 (`.venv/bin/python scripts/check_licenses.py python`). If the metadata is wrong, add an override in scripts/license_policy.yaml (`overrides:`), and add a forbidden package to `forbidden_packages`. Register the dependency in the docs/LICENSES.md 'Componentes destacados' table (columns: Componente | Licencia | Uso).
4. STEP 2 - System engine or model (if new): add the apt install to the group's stage in workers/Dockerfile (e.g. `FROM base AS worker-media`). Download models at build time in a separate stage, with a pinned revision and a SHA-256 check (pattern: the `rembg-model` stage, `ARG REMBG_MODEL=u2net`, `ARG REMBG_MODEL_SHA256=...`, `sha256sum -c -`), then `COPY --from=` it. Workers have no internet access. Add the setting to packages/core/core/settings.py (e.g. `REMBG_MODEL: str = "u2net"`, `REMBG_HOME: Path`), to .env.example, to the worker's environment in docker-compose.yml and, if needed, to scripts/gen_coolify_compose.py. The CI must install the engine or model in .github/workflows/ci.yml, job `python` ('Motores del sistema' step, or a dedicated step that checks the model's SHA-256 and exports `REMBG_HOME=$RUNNER_TEMP/...` to $GITHUB_ENV).
5. STEP 3 - Options model in packages/tools/tools/<grupo>/specs.py: a `class XxxOptions(BaseModel)` whose fields use `core.options.opt(default, es_label, en_label, advanced=False, labels={value: (es, en)}, show_if={other_field: (values,)}, widget='textarea'|'datetime-local'|'email'|'tel'|'url', ge=, le=, pattern=, max_length=)`. Use `Literal[...]` for enums and reuse the shared constants (COLOR_PATTERN, PAPERS, GRID9, FONTS in core/options.py; parse_page_ranges for 'paginas'). The web form is generated from x-title, x-labels, x-advanced and x-show-if (8.2.3 in docs/spec/08-8-frontend-y-seo.md). Secret fields go in `secret_fields` (they are published with writeOnly and format password, and sealed per job).
6. STEP 4 - Register the ToolSpec by appending to the module's `SPECS: list[ToolSpec]` through the group helper: `media(...)` or `image(...)` in packages/tools/tools/media/specs.py (where='server', worker_group='media', launch=True, time_limit=900; image() sets category='image' and phase='F5'), or `ToolSpec(...)` directly. Fields: slug_es and slug_en (from spec 07), name_es/name_en, options class, inputs (extensions, e.g. ('psd','psb')), outputs (add 'zip' when the tool takes batches, A.0), impl='tools.<grupo>.<modulo>:<func>', summary_es/summary_en (one line, used as H1 subtitle and meta description), related=(slugs_es...). Optional: cost_class='heavy' (quitar-fondo), time_limit, max_files, queue_kind='light'|'heavy'|'embed' (queue becomes '<group>.<kind>'), route=lambda opts: (group, queue) for per-option routing (pdf-a-word 'fiel'), cost=lambda opts: class, canonical_of='<slug>' for aliases, indexable, phase. A new group module must also be listed in SPEC_MODULES in packages/core/core/registry.py. Specs must NOT import engines: tests/test_core.py::test_registry_does_not_import_engines checks this, and D-01 sets the specs.py-per-group layout.
7. STEP 5 - Implementation in packages/tools/tools/<grupo>/<modulo>.py (e.g. media/fotos.py:run_psd, media/fondo.py:run). The signature is `def run(ctx: ToolContext) -> list[dict]`, and engine imports stay inside the function. Helpers in packages/tools/tools/base.py: `open_image(path, ctx.settings.IMAGE_MAX_PIXELS)` (pixel-bomb guard, 12.3); `run_engine(args, cwd=ctx.work, timeout=..., mem_mb=..., limit_data=..., ok_codes=...)` for any external program (empty env, setsid, kills the process group on timeout, GPL engines only this way); `derived_name(inp.name, '-sufijo', ext)`; `dst = ctx.output(name)` (call it once per file, since every call returns a new free name); `ctx.report(fraction, msg)`; `ctx.charge('heavy')` when the tool turns out to need extra work; `ctx.locale` with a `NOTES = {'es': {...}, 'en': {...}}` dict for text placed inside results; `ctx.handoff(group, stage)` for multi-queue flows. Batch output goes through `tools.pdf.common.with_batch_zip(ctx, outputs, 'nombre.zip')` (A.0). Return [{'path': str(dst), 'name': name, 'note': optional}]. Errors: `raise ToolError(ErrorCode.X, 'detalle')`. For a new code or a translated detail key, add it to packages/core/core/errors.py (ErrorCode and MESSAGES es/en, e.g. 'ai_empty'), then regenerate docs/ERRORS.md. Codes the browser shows directly also go in apps/web/messages/{es,en}.json under `errors`.
8. STEP 6 - Input type detection (only for a new input extension): add MIME, FAMILIES and the signature to packages/core/core/filetype.py. Port the same rule to packages/client-tools/src/filetype.ts (D-115: both detectors must agree), add cases in scripts/fixtures/filetype_cases.py and regenerate tests/fixtures/filetype-cases.json (`python scripts/fixtures/filetype_cases.py`; `--check` verifies it; tests: tests/test_filetype_cases.py and packages/client-tools/test/filetype.test.ts). `core/jobs.create_job` rejects uploads whose detected type does not match `spec.inputs` (filetype.matches).
9. STEP 7 - Celery and API need no per-tool work. tools/tasks.py:execute/run_job is generic: it loads the spec, validates the options, builds the ToolContext and calls load_impl(spec). The queue is `worker_group` or `worker_group.queue_kind` and comes from spec.target(options) at enqueue. GET /v1/tools (apps/api/app/routers/tools.py) publishes spec.to_public() with `enabled`. POST /v1/jobs (apps/api/app/routers/jobs.py -> core/jobs.create_job) validates options, files, plan limits and idempotency. Add `task_routes` in packages/core/core/celeryapp.py only for extra Celery tasks that are not run_job (as tools.ai.chat.answer and retrieve). A thematic flag (HEVC_DECODE_ENABLED and similar) needs the slug in THEMATIC_TOOLS in packages/core/core/flags.py AND in THEMATIC in apps/web/src/lib/flags.ts, plus the env var in docker-compose.yml, gen_coolify_compose.py (LIMITS) and .env.example. Per-tool kill switch at runtime: TOOL_<SLUG>_ENABLED=false (an operator setting, not the way a batch ships an unfinished tool; see STEP 12).
10. STEP 8 - Web: nothing per tool for a standard server tool. apps/web/src/app/[locale]/[slug]/page.tsx renders `ToolRunner` with clientSpec(tool) from packages/registry/registry.json; OptionsForm builds the controls; apps/web/src/lib/csp.ts adds Turnstile automatically when where != 'client'; the limits table, breadcrumbs, JSON-LD, related tools and 'Seguir con otra herramienta' all come from the registry. Add a component and a branch in page.tsx only for special UI (e.g. HeicHelp when HEVC is off: HEVC_TOOLS in apps/web/src/components/HeicHelp.tsx). If the tool is a converter ('x-a-y'), check the sets in apps/web/src/lib/conversions.ts (FORMAT_OPTION, GENERIC, NAMED, NOT_CONVERTERS) and apps/web/test/conversions.test.ts, because convertir-archivo builds its routes from the registry (D-116).
11. STEP 9 - Regenerate: `.venv/bin/python scripts/export_registry.py` (writes packages/registry/registry.json; the CI runs `--check`), `.venv/bin/python scripts/gen_docs.py` (rewrites docs/TOOLS.md and docs/ERRORS.md in full) and, if workers changed, `.venv/bin/python scripts/gen_coolify_compose.py` plus `--check` and `--validate`, and `docker compose -f docker-compose.yml config --quiet`.
12. STEP 10 - Tests: pytest file tests/test_<tema>.py (e.g. tests/test_imagenes_servidor.py). Import `from test_tools import make_ctx, run` and call `run('psd-a-png', make_ctx('psd-a-png', [src], {opts}))`. Assert the effect on the output bytes (pixels, number of pages, text, EXIF, ZIP entries, names such as 'cartel-capas.zip'), the A.0 batch ZIP and the error codes (e.g. CORRUPT_FILE, INVALID_OPTIONS via spec.options.model_validate). Guard missing engines with `pytest.importorskip('rawpy')`, `pytest.mark.skipif(not shutil.which(...))` or a model-presence skip (`needs_model`). Build samples in the test or in scripts/fixtures/generate.py (`fixtures_dir` fixture). Playwright: tests/e2e/<tema>-f<fase>.spec.ts against the static page (labels, defaults, show_if toggling, accept attribute, noindex when disabled), e.g. tests/e2e/imagenes-servidor-f5.spec.ts. Full-stack runs belong in tests/e2e/servidor.spec.ts (project 'servidor', docker compose).
13. STEP 10b - Contract and Anexo A tables (G0-A, D-135): tests/test_contrato_opciones.py checks every registered tool automatically (published options_schema equal to the model and registry.json, defaults valid, and every ge/le/pattern/max_length/min_length/Literal/max_items/min_items bound rejected with INVALID_OPTIONS by POST /v1/jobs), but two tables are per tool. (a) tests/anexo_a_minimos.py: add a `MINIMOS` entry `"<slug_es>": {"<campo>": ..., ...}` with each Anexo A option under its schema field name: `D(default)`, `E(default, *values)` for lists, `R(default, ge, le)` for ranges, `X` when the Anexo sets no default, `S` for a password (shared groups such as IMAGENES_A_PDF can be reused for several slugs); an option or list value the batch does not implement yet goes in `PENDIENTES` as `("slug", "campo"): "<lote que lo resuelve>"` (or `("slug", "campo=valor")`), and test_anexo_a_pending_is_still_missing fails once it appears in the schema without moving to `MINIMOS`. (b) For every required option (no default in the schema), add a valid sample to `REQUIRED_SAMPLES` in tests/test_contrato_opciones.py, e.g. `("web-a-pdf", "url"): "https://example.com/"`; test_defaults_are_valid raises KeyError without it.
14. STEP 11 - Docs per batch: PLAN row, PROGRESS section and counts, D-NNN rows in DECISIONS, LICENSES rows, the regenerated TOOLS.md and ERRORS.md, a DEPLOY-CHECKLIST '- [ ] Lote X de Fn con la pila completa: ...' item for anything unverifiable without Docker or real samples, and ARCHITECTURE when the flow changes (see docs_to_update_per_batch). If the tool has a PDF24 equivalent, edit its row in config/pdf24.yaml: change `slug:Fn` to the bare `slug` once the tool is registered (gen_docs fails while a registered slug keeps its `:Fn`), or add the slug to `equivalentes` when the row had none.
15. STEP 12 - A tool that is not ready (01-1 rule 7: it fails its 16.5/16.6 tests, lacks the 8.2 content in es or en, or has no valid sample) ships off: set `default_enabled=False` in its ToolSpec (D-134) and add its reason under `herramientas:` in config/tools-notes.yaml (`<slug_es>: "<motivo y qué falta>"`). gen_docs then lists it in 'Desactivadas y por qué' and refuses to run without the reason; the API, the web (noindex, out of the sitemap) and the admin panel (locked_off) treat it as off, and only `TOOL_<SLUG>_ENABLED=true` turns it on. Do NOT ship a tool off through an env var in .env.example/compose or a feature_flags row: those do not reach TOOLS.md. A tool switched off by a thematic flag needs its flag in THEMATIC_TOOLS/THEMATIC and a reason under `temas:` instead. When the tool becomes ready, remove `default_enabled=False` and its `herramientas:` entry in the same commit.

## Herramienta de navegador

1. Reference batch: F5 lote B1 (jpg-a-png ... png-a-ico, convertir-imagen, svg-a-png, svg-a-jpg, crear-favicon, quitar-metadatos-foto, imagen-a-base64; D-79 to D-86). Traced example: crear-favicon.
2. STEP 1 - Spec: in packages/tools/tools/client/specs.py add an Options class (e.g. `class FaviconOptions(BaseModel)` with opt(...) fields per the Anexo A file, here docs/spec/a-10-a-10-imagenes.md or a-1-a-1-crear.md) and append an entry to SPECS with the helper `client(slug_es, slug_en, name_es, name_en, Options, inputs, outputs, summary_es, summary_en, related=..., max_files=...)` (where='client', launch=True, category='pdf' by default) or `image(...)` (category='image', phase='F5'). A hybrid tool passes where='hybrid', worker_group, impl='tools.<grupo>.<mod>:run' and also needs a server implementation (server recipe). Example: `image("crear-favicon", "favicon-generator", "Crear favicon", "Favicon generator", FaviconOptions, ("png","jpg","webp","svg"), ("ico","png","zip"), "...", "...", max_files=1, related=("png-a-ico","svg-a-png"))`.
3. STEP 2 - Implementation in packages/client-tools/src/<modulo>.ts (e.g. imageconvert.ts `export async function crearFavicon(files: InFile[], o: FaviconOptions, env: ImageEnv): Promise<ToolResult>`). Return `{ outputs: [{ name, bytes, mime }], notes: [...] }`. Use the helpers in src/common.ts (ToolError with stable codes, derivedName, stem, withBatchZip for A.0 batches), src/rasters.ts checkPixels (pixel limit), localized notes through env.locale ('es' | 'en'), and progress through env.progress. A format-shortcut tool can instead be an entry in the `FIXED_FORMAT` map of imageconvert.ts, which reuses convertirImagen.
4. STEP 3 - Dispatch: in packages/client-tools/src/index.ts add the slug to the `CLIENT_TOOLS` const array, import the function and add a `case "<slug>":` to the `runClientTool` switch. Pass only the needed pieces of ClientEnv (fonts, codec, wasm, renderer, encoder, toPng, rasterize, renderMaxPixels, locale). packages/client-tools/test/imageconvert.test.ts checks that the batch-B1 slugs are in CLIENT_TOOLS.
5. STEP 4 - Dependencies and WASM: pin exact versions in packages/client-tools/package.json (or apps/web/package.json for page-only libraries such as konva and qr-code-styling) and run `npm install` so package-lock.json updates. Check the license against the FRONTEND allowlist of 11 (`python3 scripts/check_licenses.py npm`). Never ffmpeg.wasm or @ffmpeg/core (GPL); SheetJS only from cdn.sheetjs.com with a pinned version. Add the dependency to docs/LICENSES.md. WebAssembly is served same-origin from /codecs/ with a content hash in the name (D-80): add it to `WASM_SOURCES` in apps/web/scripts/wasm-assets.mjs (copied by apps/web/scripts/copy-wasm.mjs, URLs exposed to the worker via NEXT_PUBLIC_WASM_URLS in next.config.ts) and to the WasmName type and loader in packages/client-tools/src/wasmcodecs.ts. Load heavy WASM only when the user picks a file, inside the Web Worker (8.3 in docs/spec/08-8-frontend-y-seo.md).
6. STEP 5 - Worker runtime: apps/web/src/workers/client-tool.worker.ts calls runClientTool(slug, files, options, env) and supplies fonts (/fonts/Noto*.ttf), the canvas codec, the wasm loader and PDFium. Change it only when a new env capability is needed. apps/web/src/lib/client-runner.ts posts the message. ToolRunner decides browser or server through spec.where (hybrids go to the server above CLIENT_MAX_MB or for unsupported cases).
7. STEP 6 - Page: automatic through apps/web/src/app/[locale]/[slug]/page.tsx -> ToolRunner (notice 'Tu archivo no sale de tu dispositivo', options form, result, next tools). Only a tool with a bespoke UI (editor, camera, QR, collage) gets a component in apps/web/src/components/f<fase>/ and a branch in the page.tsx chain (`tool.slug_es === "crear-collage" && !disabledByEnv(...) ? <CollageView .../>`), plus a UI namespace with identical keys in apps/web/messages/es.json and en.json (apps/web/test/content.test.ts checks key parity). Camera or other Permissions-Policy needs and CSP changes go in apps/web/src/proxy.ts and apps/web/src/lib/csp.ts (escaner-pdf and crear-collage pattern).
8. STEP 7 - Tests: Vitest in packages/client-tools/test/<tema>.test.ts. Call `runClientTool(slug, [{name, bytes}], options, env())`, where env() = { codec: nodeCodec(log), wasm: nodeWasm, fonts: reads apps/web/public/fonts }, from test/image-node.ts and test/wasm-node.ts. Use samples generated with Pillow by test/gen_images_f5.py into test/images-f5.fixture.ts (Base64, no third-party rights). Decode the outputs and assert pixels, ICO directory, EXIF, ZIP entries and notes. Playwright: tests/e2e/<tema>-f5.spec.ts with `watchUploads(page)` (no non-GET request leaves the page, 16.1: 'las herramientas cliente no envían el archivo a la red'), a CSP violation listener in beforeEach, the run() and download() helpers, and checks on the downloaded bytes (pattern: tests/e2e/imagenes-f5.spec.ts).
9. STEP 7b - Same per-tool tables as the server recipe (STEP 10b): a `MINIMOS` row (or `PENDIENTES` with its batch) in tests/anexo_a_minimos.py, a `REQUIRED_SAMPLES` entry in tests/test_contrato_opciones.py for each required option, the config/pdf24.yaml row (`slug:Fn` -> `slug`), and, if the tool is not ready, `default_enabled=False` plus its reason under `herramientas:` in config/tools-notes.yaml (server STEP 12). Run `.venv/bin/pytest -q tests/test_contrato_opciones.py tests/test_docs.py`.
10. STEP 8 - Regenerate registry.json and TOOLS.md (scripts/export_registry.py, scripts/gen_docs.py). Run `npm test`, `npm run typecheck`, `npm run build`, then Playwright with `next start -p 3100` (CI env: PORT=3100 PUBLIC_WEB_URL=http://127.0.0.1:3100 BETTER_AUTH_URL=http://127.0.0.1:3100 AUTH_SECRET=...; set PW_CHROMIUM_PATH to use a local Chromium) and `npx playwright test -c tests/e2e/playwright.config.ts --project=navegador`. Update the docs (PLAN, PROGRESS, DECISIONS, LICENSES).

## Herramienta de IA

1. Reference batch: F3 lote B (generador-de-preguntas, pdf-a-fichas, pdf-a-presentacion, traducir-pdf; D-130 to D-133). Traced example: pdf-a-fichas. Specs to read: docs/spec/06-6-ia-con-modelos-gratuitos-de-openrouter.md (6.1 OpenRouter facts, 6.2 model needs, 6.3 requests per task and budget, 6.4 local models, 6.5 JSON, cache and prompt-injection guard, 6.6 consent text and fake provider), the catalog line in 07-7-catalogo-completo-de-herramientas.md and the plan limits in 09-9-backend.md §9.3 (config/plans.yaml: ai_requests_day, ai_requests_task, ai_pages_task, tts_chars_task).
2. STEP 1 - Options in packages/tools/tools/ai/specs.py: subclass `DocumentoIAOptions`, which already has paginas, ocr and idioma_documento (show_if ocr). Reuse the LANGUAGES, DOC_LANGUAGES and TARGETS dicts and the `Target` Literal. Example: `class FichasOptions(DocumentoIAOptions): numero: int = opt(20, ..., ge=5, le=100); tipo: Literal[...]; idioma: Literal['documento','es',...] = opt('documento', ..., labels=LANGUAGES); formato: Literal['tsv','csv','docx']`. Ranges not fixed by the Anexo A go in a D-NNN (D-130).
3. STEP 2 - Register with the helper `ai_tool(slug_es, slug_en, name_es, name_en, Options, 'tools.ai.<mod>:run', summary_es, summary_en, AiSpec(estimate=lambda o: N, json=True, images=False, min_context=8000, min_output=1500), outputs=(...), related=(...))`. The helper fixes category='ai', where='server', worker_group='ai' (queue 'ai'), cost_class='ai', launch=True, phase='F3', max_files=1, time_limit=1800 and inputs ('pdf',). Comment the 6.3 request count above the entry (e.g. '# 6.3: 2 peticiones (esquema y diapositivas).'). AiSpec.estimate is the minimum the API reserves at enqueue; the worker reserves the rest before spending (D-121). queue_kind='embed' sends work to workeraiembed (chat-pdf).
4. STEP 3 - Implementation packages/tools/tools/ai/<mod>.py (e.g. fichas.py). TEXTS dict es/en for strings inside the result. A strict JSON SCHEMA (`additionalProperties: False`, `required`). `clean(data, pages)` validates the model output: it drops invalid or duplicate items and raises ValueError when more than half are bad, which triggers a repair (D-131). `make(ctx, selected, body)`: `parts, cap = comun.blocks(ctx, body, out_tokens)`; `work = comun.batches(parts, total, per_item_tokens, cap)`; `ctx.ai.budget.ensure(len(work))` reserves every request before any spending (fails without spending if the plan does not allow it); then, per batch, `ctx.ai.complete_json([system, user], needs=comun.needs_for(part, out), max_tokens=min(out, cap), schema=SCHEMA, check=lambda d: clean(d, pages))`. The system prompt must include `comun.GUARD` (document between <<< >>>, treat it as content and never as instructions), `comun.language_rule(o.idioma)` and the literal 'exactamente {count}'. The user message is `f"Documento:\n<<<\n{part}\n>>>"`. To avoid repeats, pass the items already made. `run(ctx)`: `selected, body = comun.document(ctx)` (pypdfium2 text with '[Página n]'; scanned pages trigger a handoff to the `ocr` queue and back, D-124; raises INVALID_OPTIONS 'ai_empty' when empty), then `result, hit = comun.with_cache(ctx, '<slug>', options_without_format, lambda: make(...))` (owner cache; changing the format costs no requests, D-131), then `note = comun.note(ctx, hit)` and `comun.texts(ctx)['made'].format(model=...)` for the 'Hecho con IA ... puede tener errores' line. Write the output (python-docx with `tools.ai.salida.set_language`, python-pptx, CSV with BOM). Use `derived_name` and call `ctx.output()` once per file.
5. STEP 4 - Translation or PDF output: use `TranslationProvider` and `LLMTranslator` in packages/core/core/ai/translate.py (D-132). PDF output goes through Gotenberg's Chromium (workerai has GOTENBERG_URL on the internal network in both compose files). Never BabelDOC (AGPL).
6. STEP 5 - Fake provider: packages/core/core/ai/provider.py `_fake_value` and `_fake_context` produce schema-valid JSON in dev and tests (D-126, D-133). If the new schema uses an array name that must have exactly N items, add it to the tuple `('preguntas','fichas','diapositivas','secciones')`, or add a context rule. Fakes exist only with APP_ENV=development or in tests (01-1 rule 7).
7. STEP 6 - No per-tool API work. POST /v1/jobs -> core/jobs.create_job: when spec.ai is set it calls `prepare(...)`, which needs an account (anonymous users have 0 requests, 401), checks ai_consent (400 without it, 6.6), checks model availability and reserves AiSpec.requests_for(options) in Valkey and usage_daily. tools/tasks.py builds AIClient and JobBudget and settles the budget at the end. GET /v1/ai/budget (apps/api/app/routers/ai.py) lists the AI tools from registry.specs. Tools in category 'sign' or whose slug contains firma, certificado, contacto, vcf, calendario, ics, eml, msg, correo, pst or mbox can never create an AI client (packages/core/core/ai/__init__.py is_excluded, 16.3).
8. STEP 7 - Web: automatic. ToolRunner shows AiPanel (apps/web/src/components/AiPanel.tsx: 6.6 notice text, consent checkbox, remaining requests, 'no disponible temporalmente') because costClass === 'ai'. The shared texts live in the `ai` namespace of apps/web/messages/{es,en}.json. apps/web/test/ai.test.ts checks the literal notice, CONSENT_VERSION parity and that every AI tool is a server tool of class ai outside the excluded categories.
